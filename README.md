# Практическая работа №4. PHP: основы языка, запросы и обработка HTML-форм

Дисциплина: Технологии разработки программного обеспечения.

## Что сделано

Небольшое PHP-приложение «Заявки сотрудников» без MVC:

- в шапке выводится версия приложения и текущая дата (считаются средствами PHP);
- таблица сотрудников из `data/employees.csv` (чтение через `fgetcsv`);
- фильтр таблицы по отделу через GET-параметр `department`;
- форма заявки из четырёх полей (ФИО, email, отдел, стаж), метод POST;
- серверная валидация, ошибки возле полей, введённые значения не теряются;
- все пользовательские значения выводятся через `htmlspecialchars`;
- блок «Проверка сценариев» прогоняет `data/form_cases.json` через ту же валидацию.

Технологии: PHP 8.0+, HTML, CSS. Библиотеки и composer не нужны.

## Требования

## Функции (src/functions.php)

| Функция | Назначение |
|---------|-----------|
| `e()` | экранирование значения через `htmlspecialchars` |
| `loadEmployees()` | чтение `employees.csv` через `fgetcsv` |
| `makeEmployee()` | преобразование одной строки CSV в массив с нужными типами |
| `getDepartments()` | уникальные отделы для фильтра и формы |
| `filterEmployees()` | фильтр по отделу (пустое значение = все записи) |
| `averageExperience()` | средний стаж |
| `readFormInput()` | чтение `$_POST` через `??` и `trim` |
| `validateInput()` | серверная валидация, возвращает массив ошибок |
| `loadFormCases()`, `runFormCases()` | сценарии из `form_cases.json` |

## Правила валидации

| Поле | Правило |
|------|---------|
| ФИО | обязательное, от 2 до 100 символов |
| Email | обязательный, проходит `FILTER_VALIDATE_EMAIL` |
| Отдел | должен быть из списка отделов `employees.csv` |
| Стаж | обязательный, целое число от 0 до 50 |

Заявка после успешной проверки только показывается на странице, в файл она не записывается.

## GET и POST

- **GET** передаёт параметры в адресе (`?department=Разработка`). Подходит для фильтров и поиска: адрес можно сохранить в закладки и отправить другому человеку. Данные видны в адресной строке, и их не стоит использовать для паролей.
- **POST** передаёт данные в теле запроса. Подходит для форм, которые что-то создают или меняют. Данные не попадают в адрес, а объём может быть больше.

В этой работе фильтр отдела работает через GET, а форма заявки через POST.

## Назначение htmlspecialchars

Функция превращает специальные символы (`<`, `>`, `&`, кавычки) в безопасные коды (`&lt;`, `&gt;` и т.д.). Тогда введённая пользователем строка вроде `<script>alert(1)</script>` показывается как текст и не выполняется как HTML и JavaScript (защита от XSS). В проекте для этого используется функция `e()`, ею оборачивается каждое значение, пришедшее от пользователя или из файла.

## Путь данных

```
Форма (браузер)
   | POST: name, email, department, experience
   v
public/index.php: readFormInput()    берёт значения через ??, убирает пробелы (trim)
   v
validateInput()                      проверяет и возвращает массив ошибок
   v
index.php: HTML                      показывает ошибки возле полей или подтверждение,
                                     все значения проходят через e() (htmlspecialchars)
   v
HTTP-ответ в браузер

employees.csv -> loadEmployees() -> makeEmployee() -> filterEmployees() -> таблица в HTML
```

## Ошибки PHP

В `public/index.php` показ всех ошибок включается только при запуске через встроенный сервер (`PHP_SAPI === 'cli-server'`): `display_errors` и `error_reporting(E_ALL)`. На рабочем сервере эти настройки не включаются.

## Ограничения

- Заявки не сохраняются: после обновления страницы данные формы пропадут.
- Повторная отправка формы при обновлении страницы выполнит POST заново (в следующих работах решается redirect после POST).
- Всё в одном файле `index.php`, без разделения на слои. MVC появится в следующих работах.
